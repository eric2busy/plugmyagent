Set up your agent:

Pick your tab, follow the steps, end with a working agent. Same playbook for all fourteen: account, app, first tool, first test. Then connect your first API.

ChatGPT

10 minutesBeginnerFree to start
What you end up with

ChatGPT with tools connected, ready to fetch live data. Free tier works for chat; connecting your own tools (MCP) needs a paid plan. Start free, upgrade when you want tools.

01Create your account

Open chatgpt.com in your browser and sign up. Use an email address you actually check: login codes and important notices go there.

What success looks like

You are logged in at chatgpt.com and you see the chat window.

02Get the app

Install the ChatGPT app from the App Store (iPhone) or Google Play (Android) and log in with the same account. The app adds voice, image, and camera input on top of chat.

What success looks like

You are logged in on your phone. Same agent, same history, two places.

03Connect your first tool

Open Settings and look for Apps / Connectors. Start with a prebuilt one: Gmail, Google Drive, or Calendar. Grant access once and ChatGPT can read from it when you ask.

For your own tools (APIs, MCP servers), you need a paid plan: Plus, Pro, or Business. On a paid plan, turn on Developer Mode in Settings, then add a remote MCP server by its URL. The server's tools appear in your chats.

What success looks like

You ask about something only the connected tool knows, and it answers with live data instead of guessing.

04Run the test

Ask one question only the connected tool can answer. Then read guide 004 to connect your first API in 10 minutes: the same three moves (get access, connect it, test it) work here.

What success looks like

A live answer from your tool, not a guess from memory. You have a working agent.

When something goes wrong

I cannot find Developer Mode / MCP

Custom MCP servers need a paid plan (Plus, Pro, or Business) and Developer Mode on. On the free plan, use the prebuilt Apps instead.

It answered from memory instead of using the tool

Name the tool explicitly: "Use the [name] tool and read the number from its response." Then ask again. Guide 004, section 05 covers this fix.

Codex

15 minutesIntermediateNeeds a paid ChatGPT plan
What you end up with

OpenAI's coding agent working in your projects, with your tools connected. Codex is not a separate subscription: it is included with ChatGPT Plus, Pro, Business, and Edu plans. It runs in a desktop app, in your editor, and in the terminal, and all three share one config file.

01Create your account

Sign up at chatgpt.com if you have not already. Codex rides on that account, so there is nothing new to register. On a free plan you may see limited trial access; the full agent unlocks on Plus or higher.

What success looks like

You are logged in at chatgpt.com on a plan that includes Codex.

02Get the app

Install the Codex app for your computer, or install the CLI with npm i -g @openai/codex if you prefer the terminal. Sign in with your ChatGPT account when it asks. The app, the CLI, and the editor extension all read the same settings.

What success looks like

Codex opens, shows your account, and is ready in an empty project.

03Connect your first tool

Codex reads MCP servers from ~/.codex/config.toml, and note the format: TOML, not the JSON most other agents use. The easy path is to run codex mcp add and let the CLI write the entry. By hand, a server is a block that starts with [mcp_servers.name] followed by its command or URL. Restart Codex after editing the file.

What success looks like

Run /mcp in Codex and your server is listed as connected.

04Run the test

Give it one small job that needs the connected tool, in a project you can afford to experiment on. Then read guide 004 to connect your first API: the same three moves work here.

What success looks like

Codex calls the tool, shows you the result, and any change it made is one you can review and undo.

When something goes wrong

My server never shows up

The usual cause is a JSON block pasted into the TOML file. Codex config is TOML with a [mcp_servers.name] header. Fix the format, save, and restart Codex.

It says my plan does not include Codex

Free and Go plans get limited trial access at most. Codex is included with Plus, Pro, Business, and Edu; there is no separate Codex plan to buy.

Copilot

10 minutesBeginnerFree to start
What you end up with

GitHub Copilot in agent mode, calling your tools from inside VS Code. Copilot has a free tier for light use, and paid plans raise the limits. The agent lives in your editor, so setup means VS Code, your GitHub account, and one config file.

01Create your account

Sign up at github.com. Copilot activates against that account, and the free tier is enough to follow this whole guide.

What success looks like

You are logged in to GitHub and can open your profile.

02Get the app

Install VS Code, sign in with your GitHub account, and add the GitHub Copilot and Copilot Chat extensions from the marketplace. Open the Chat view and pick Agent in the mode dropdown.

What success looks like

The Chat view answers you, and Agent is one of the modes you can pick.

03Connect your first tool

Add an MCP server in a file named .vscode/mcp.json inside your project. Heads up: the top-level key in this file is "servers", not the "mcpServers" most other agents use. Or run the Command Palette action MCP: Add Server and let VS Code draft it. Connected tools appear in the agent's tool picker.

What success looks like

Your server starts without an error and its tools show in the picker.

04Run the test

Ask the agent one question only the connected tool can answer. Then read guide 004 to connect your first API: the same three moves work here.

What success looks like

The agent calls the tool and answers from live data, not a guess.

When something goes wrong

There is no Agent mode in the dropdown

Update VS Code and both Copilot extensions, and confirm you are signed in to GitHub. Agent mode needs current versions of all three.

My server shows an error

Check the JSON in mcp.json first. Then run the server's command in a terminal yourself: if it fails there, it will fail for Copilot too, and the terminal shows the real error.

Cursor

10 minutesBeginnerFree to start
What you end up with

Cursor editing your codebase with your MCP tools one prompt away. Cursor is an AI code editor: you chat with an agent that can read and change your project. Its free tier is enough to set up and test your first tool.

01Create your account

Sign up at cursor.com, or create the account inside the app when it first opens. Use an email you actually check.

What success looks like

You are signed in and Cursor shows your account in Settings.

02Get the app

Download Cursor for Mac, Windows, or Linux and sign in. Open one of your project folders so the agent has something real to work on.

What success looks like

Your project is open and the agent panel answers a hello.

03Connect your first tool

Open Settings, find MCP, and choose Add new global MCP server. Or edit ~/.cursor/mcp.json directly and add your server under "mcpServers". For one project only, put the same file at .cursor/mcp.json in the repo. A green toggle next to the server means its tools are live.

What success looks like

The server's toggle is green and its tools are listed under it.

04Run the test

Ask the agent one question only the connected tool can answer. Then read guide 004 to connect your first API: the same three moves work here.

What success looks like

The agent calls the tool and answers from its response.

When something goes wrong

The server toggle is red

The command failed to start. Run the same command in a terminal to see the real error, and use absolute paths in args: relative paths resolve differently inside the editor.

The agent ignores my tools

Cursor caps how many tools the agent can see at once. Disable servers you are not using in Settings, then ask again and name the tool you want used.

Devin Desktop

10 minutesBeginnerFree to start
What you end up with

The Cascade agent set up in Devin Desktop, with your tools connected. First, a rename worth knowing: the editor called Windsurf became Devin Desktop in 2026. Same editor, same Cascade agent, new name on the door. Old Windsurf guides mostly still apply, with one config move covered below.

01Create your account

Sign up in the app or at devin.ai with the account you will code with.

What success looks like

You are signed in and the editor opens to your account.

02Get the app

Download Devin Desktop for your computer and sign in. Open a project folder and find the Cascade panel: that chat is your agent.

What success looks like

Cascade answers a test message about your open project.

03Connect your first tool

In the Cascade panel, open the ... menu in the MCPs section and choose Open MCP config file. Current versions keep it at ~/.config/devin/mcp_config.json (older Windsurf installs used ~/.codeium/windsurf/mcp_config.json). Add servers under "mcpServers". One gotcha: remote servers take the key "serverUrl" here, not "url".

What success looks like

Your server appears in the MCPs list and Cascade can call its tools.

04Run the test

Ask Cascade one question only the connected tool can answer. Then read guide 004 to connect your first API: the same three moves work here.

What success looks like

Cascade calls the tool and answers from its response.

When something goes wrong

My Windsurf setup stopped working after the rename

Your config file moved. Copy the "mcpServers" block from ~/.codeium/windsurf/mcp_config.json into ~/.config/devin/mcp_config.json and restart the app.

My remote server is ignored

Check the key name: remote servers need "serverUrl" in this app. A block copied from a Cursor guide with "url" will be silently skipped.

Gemini

10 minutesBeginnerFree to start
What you end up with

Gemini for everyday help in the app, plus the Gemini CLI for connecting your own tools. One Google account covers both. The app connects Google's own services; your own MCP servers plug into the free Gemini CLI, and this tab sets up both halves.

01Create your account

A Google account is the whole signup. Open gemini.google.com and sign in with it.

What success looks like

Gemini greets you by account and the chat window is ready.

02Get the app

Install the Gemini app on your phone for chat and voice. For tools, install the CLI on your computer with npm i -g @google/gemini-cli and sign in with the same Google account; the CLI includes a free tier.

What success looks like

The app is signed in on your phone, and the CLI answers a test prompt in your terminal.

03Connect your first tool

In the app, open Settings and turn on the connected apps you want (Gmail, Drive, Maps). For your own MCP servers, open ~/.gemini/settings.json and add them under "mcpServers", then start the CLI and run /mcp to confirm they loaded.

What success looks like

/mcp lists your server as connected, with its tools.

04Run the test

Ask the CLI one question only your tool can answer. Then read guide 004 to connect your first API: the same three moves work here.

What success looks like

The CLI calls the tool and answers from live data.

When something goes wrong

/mcp does not list my server

Almost always the JSON: one bad comma and the whole settings file is skipped. The CLI also prints config errors at startup, so scroll up in the terminal after launching it.

The app cannot see my server

That split is by design today: custom MCP servers live in the Gemini CLI, not the consumer app. Use the CLI for tool work, and the app for chat.

Instinct

10 minutesBeginnerFree during beta
What you end up with

An Instinct agent with its own phone number and email, connected to your accounts, ready to act for you. Instinct is invite-only: you join the waitlist or get an invite link from an existing member.

01Get an invite

Two doors. Door one: join the waitlist at app.instinct.com and wait for your invite. Door two: get an invite link from someone who already has Instinct. Each member gets 5 invites to share. If you know a member, door two is faster.

What success looks like

You have an invite link and can sign up.

02Sign up with your phone

Open your invite link and sign in with your phone number plus a text code. You must be 18 or older. There is no app to install: Instinct lives in your messages (iMessage, WhatsApp, SMS) and on calls.

What success looks like

You are signed in and your Instinct agent has its own phone number and email address.

03Connect your accounts

Connect your email, calendar, and messaging apps. This is what turns Instinct from a chatbot into an agent: with your accounts connected, it can book, buy, follow up, and call on your behalf instead of just answering questions.

What success looks like

You ask about something only your connected accounts know, and it answers with live data instead of guessing.

04Hand it one real job

Give it something that needs action, not just an answer: book a table, follow up on an email thread, research and buy a product. Instinct's agents coordinate with each other through a trusted network (Instinct-to-Instinct only), including group chats where your friends do not need accounts.

What success looks like

It does the job and reports back with proof, not just a plan. You have a working agent.

When something goes wrong

I have no invite and the waitlist is slow

Ask around: every member gets 5 invites. One invite link from a member skips the waitlist entirely.

It answered instead of acting

Be explicit about the outcome: "Book the table for two on Friday at 7pm and send me the confirmation." The delegation recipe from guide 001 applies here: outcome, context, constraints, check.

Referral tip

New to Muse? Enter the code DGC4EX in Settings within 48 hours of joining: you get 1 billion tokens, and so does the person who invited you. Disclosure: this is our referral code. It costs you nothing, and we both earn tokens if you use it.

OpenClaw

20 minutesIntermediateFree and open source
What you end up with

An OpenClaw agent running on your own machine. This is the self-hosted path, fully yours, terminal required. Want the 10-minute phone path instead? That is the Muse tab.

01Install Node.js 22 or newer

OpenClaw runs on Node.js, version 22 or higher. Check what you have:

node --version

No Node yet, or the version is too old? Install the LTS release from nodejs.org, then close your terminal completely and open a fresh one.

What success looks like

The terminal prints a version like v22.14.0 or higher.

02Install OpenClaw

On macOS or Linux, run the official installer:

macOS / Linux
curl -fsSL https://openclaw.ai/install.sh | bash

On Windows, open PowerShell and run:

Windows PowerShell
iwr -useb https://openclaw.ai/install.ps1 | iex

Prefer npm? This works too:

npm install -g openclaw@latest
What success looks like

openclaw --version prints a version number. The command exists and your terminal knows where it lives.

03Run the onboarding wizard

openclaw onboard --install-daemon

The wizard walks you through three decisions in plain words:

  1. Which AI model powers your agent. Pick Anthropic, OpenAI, OpenRouter, or a local model via Ollama. The hosted options need an API key; the wizard asks for it and stores it securely.
  2. How the gateway runs. Accept the default: the wizard installs it as a background service so your agent keeps working when the terminal is closed.
  3. Which chat channels to connect. WhatsApp, Telegram, Discord. You can add these later too.
What success looks like

The wizard finishes without errors. Your settings live in ~/.openclaw/openclaw.json and your agent's workspace in ~/.openclaw/workspace.

04Check that it is alive

openclaw gateway status
openclaw health
What success looks like

Gateway status says running. Health reports OK. If either one complains, jump to troubleshooting below before continuing.

05Open the dashboard and say hello

openclaw dashboard

Or open http://127.0.0.1:18789/ directly in your browser. This is your agent's control room: chat, integrations, and settings in one place.

Your first message

"Hi. Tell me what you can do, and what you need from me to do it well."

What success looks like

The dashboard loads and your agent answers. You now have a working self-hosted agent.

06Connect your phone (optional)

openclaw channels login

Follow the prompts to link WhatsApp or Telegram. Message your agent from your phone and get a reply.

What success looks like

A message sent from your phone gets an answer from your agent. Same brain, new doorway.

When something goes wrong

openclaw: command not found after installing

Close the terminal completely and open a fresh one so it picks up the new PATH. Still missing? Re-run the installer and read its output for errors.

The gateway will not start, or the port is busy

Run it in the foreground to see the actual error:

openclaw gateway --port 18789

The most common cause is a second copy already running.

On Linux, the agent dies when I log out

The official docs call this out: the background service needs lingering enabled so it survives logout:

sudo loginctl enable-linger $USER
The wizard asks for a model provider and I have no API key

Two free paths: choose the local option via Ollama for a fully free setup, or grab a pay-as-you-go key from OpenRouter. Keys go into the wizard, never into a chat.

Poke

02Set your price

Poke asks you to name your monthly price. Reported prices run roughly $2 to $29 a month depending on the haggle. Offer what the service is worth to you: lower is fine, and Poke will counter if it wants more. This is the one agent where the price is a conversation, not a price list.

What success looks like

You and Poke agree on a monthly price and the subscription is active.

03Connect your first integration

Connect a service you already use: Gmail, Calendar, Notion, Linear, or Oura. Grant access once and Poke can read from it when you ask. Poke also supports Recipes (saved automations) and MCP for custom tools.

What success looks like

You ask about something only the connected integration knows, and it answers with live data instead of guessing.

04Run the test

Text Poke one question only the connected integration can answer. Then read guide 004 to connect your first API in 10 minutes: the same three moves (get access, connect it, test it) work here.

What success looks like

A live answer from your integration, not a guess from memory. You have a working agent.

When something goes wrong

Poke will not accept my price

Counter once, slightly higher. If it still will not accept, ask what it needs: the haggle is part of the product, not a bug.

It answered from memory instead of using the integration

Name the integration explicitly: "Check my [calendar / email / Notion] and read the answer from there." Then ask again. Guide 004, section 05 covers this fix.
